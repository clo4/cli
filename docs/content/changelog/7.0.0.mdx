Adds parser combinators for an argument's `parse`, and replaces `generators` with `suggest`. A CLI written for 6.1 needs changes if it calls `CLI.choice`, has an argument with `generators`, or runs `testSpec` on a root without `--help` or a `completion` subcommand.

## Breaking changes

- `CLI.choice` takes each string as its own argument: `CLI.choice(["debug", "release"])` becomes `CLI.choice("debug", "release")`. Passing an array is a compile error, and in JavaScript it throws when the value is parsed.
- An argument's `generators` is replaced by `suggest`. A suggester gets `word`, the value being typed, and what the action would get from the line so far, as strings.

  ```ts
  generators: { custom: async (tokens) => listTargets(tokens.at(-1) ?? "") }, // 6.1
  suggest: async ({ word }) => listTargets(word), // 7.0
  ```

- The `Generator` type is removed. Use `Suggester` and `SuggestInit`.
- `CLI.number` requires a digit after a decimal point. It rejects `3.`, and still accepts `3.0` and `.5`.
- `testSpec` has two new checks. `assertRootHasHelpOption` fails a root without a `--help` option, and `assertRootHasCompletionCommand` fails a root without a `completion` subcommand. Set `allowNoHelpOption` or `allowNoCompletionCommand` to skip them.

## Added

- Parsers for an argument's `parse`, which can be nested in each other:
  - `seq(...parts)` reads each part in order and gives their values as a tuple. A string part must match exactly and gives no value, so `seq(uint, "x", uint)` reads `1920x1080` as `[1920, 1080]`.
  - `optional(part)` reads the part if it's there, or gives `undefined`.
  - `many(part, min)` reads the part `min` or more times in a row. `min` defaults to 0.
  - `sepBy(part, separator)` reads the part one or more times with `separator` between them.
  - `uint` reads a whole number without a sign. `int` reads one with an optional minus sign, like `CLI.number({ int: true })`.
  - `text(...stops)` reads up to the first of `stops`, or to the end of the value.
  - `parser.map(fn)` transforms a parser's value, and keeps its help, errors and completion.
  - `parser.as(label)` labels a parser in help, as in `<width>x<height>`. `asObject()` on a `seq` gives its labelled values as an object.
  - Help shows a built-in parser as a pattern, such as `<int>(ms|s|m|h)`.
  - An error for a rejected value says what was expected and where, as in `expected ms | s | m | h after "30"`.
  - Completion offers what a parser can read next in a partly typed value. In fish, a value that can continue no longer gets a space after it.
- `CLI.complete(spec, argv, word)` returns the completions for a command line.
- `suggest` takes several suggesters. They run at the same time, and their values are offered in order.
- `CLI.print` writes to stdout directly, like `CLI.printError` does to stderr.
- `eval "$(demo completion zsh)"` installs completion in zsh. The script still works as a file on `fpath`.
- New exported types: `Parser`, `Part`, `Seq`, `Suggester`, `SuggestInit`, `Completion` and `CompleteOptions`.

## Changed

- Every description written as an indented block, starting with a newline, is dedented by its least indented line, in help and completion.

## Fixed

- A function with properties, such as a mock used as an action, type-checks in a spec.

## Documentation and development

- The site is rebuilt. The docs are at https://clo4.net/cli/docs, and the changelog at https://clo4.net/cli/changelog.
- New docs pages for parsers and suggesters, and a reference page for each part of the API.
- `GLOSSARY.md` defines the terms for parsers, completions and suggesters.
