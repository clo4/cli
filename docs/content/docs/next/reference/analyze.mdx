---
title: Analyze
description: Read a command line the way the parser does, token by token.
---

```ts
import { analyze } from "@clo4/cli/analyze";
```

For tools built around a spec: an editor that highlights a command line, a linter for scripts that call a CLI, or the [playground](/cli/). It's an entry point of its own, so a CLI that never analyzes a line never loads it.

## `analyze(spec, argv)` [#analyze]

```ts
function analyze(spec: Spec, argv: readonly string[]): Promise<Analysis>;
```

Reads `argv`, the command line after the program's name, the way [`run`](./running.mdx#run) does, without running an action. Every token is read, even after one that's wrong, so each has a reading.

```ts
const { tokens, problems } = await analyze(spec, ["build", "--jobs", "many"]);
tokens.map((t) => t.kind); // ["subcommand", "options", "value"]
problems; // [{ message: 'Invalid value "many" for --jobs: ...', token: 2, start: undefined }]
```

It rejects only if a `loadSpec` does. Commands behind a `loadSpec` are loaded as the line enters them.

## `Analysis` [#analysis]

| Field      | Type                                    | Meaning                                                 |
| ---------- | --------------------------------------- | ------------------------------------------------------- |
| `tokens`   | [`TokenReading`](#tokenreading)`[]`     | What the parser read each token as, in order.           |
| `problems` | [`Problem`](#problem)`[]`               | Everything `run` would report about the line, in order. |
| `result`   | [`ParseResult`](#parseresult)` \| null` | What the action gets, or `null` if there are problems.  |

## `TokenReading` [#tokenreading]

What one token is, by its `kind`:

| `kind`         | Other fields          | The token is                                                                                                                                       |
| -------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"subcommand"` | `command`             | A subcommand's name. `command` is the subcommand as the spec writes it, before a `loadSpec` loads it.                                              |
| `"options"`    | `options`, `attached` | One option, or several chained short options like `-xvf`, in order. `attached` is the option, argument and start of a value in the token, or null. |
| `"value"`      | `option`, `arg`       | A value of the option before it, for its argument `arg`.                                                                                           |
| `"argument"`   | `arg`                 | A positional argument for `arg`, or for none if the command has no room for it.                                                                    |
| `"separator"`  |                       | `--`, after which every token is an argument.                                                                                                      |
| `"unknown"`    |                       | An option that doesn't exist.                                                                                                                      |

## `Problem` [#problem]

| Field     | Type                  | Meaning                                                                                                                                                                                     |
| --------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `message` | `string`              | What's wrong, in the words `run` prints.                                                                                                                                                    |
| `token`   | `number \| undefined` | The index of the token it's in, or `-1` for the program's name. A problem with a command, like an argument it's missing, is in the token that names it. `undefined` for an invalid default. |
| `start`   | `number \| undefined` | Where the value starts in the token, for a value attached to its option, like `--jobs=many`.                                                                                                |

## `ParseResult` [#parseresult]

What the action gets, as [`ActionInit`](./running.mdx#actioninit) has it, and the action that runs.

| Field               | Type                                       | Meaning                                                                                             |
| ------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `args`              | `unknown[]`                                | The positional arguments, each a string or what its parser gave.                                    |
| `options`           | [`OptionArgs`](./running.mdx#optionargs)   | The options used, and the defaults of those that weren't.                                           |
| `path`              | [`CommandPath`](./running.mdx#commandpath) | The commands from the root to the selected one.                                                     |
| `argSeparatorIndex` | `number`                                   | Where `--` was among `args`, or `-1` if it wasn't used.                                             |
| `action`            | [`Action`](./running.mdx#action)           | The last option action used, or else the selected command's. A command without one prints its help. |
