A parser converts text into a value or reports why the text does not match. For example, `uint` converts `"30"` into the number `30`. `choice("s", "m", "h")` accepts one of those strings.

A parser combinator builds a parser from smaller parsers. Use `seq` to read parts in sequence, `choice` to accept alternatives, and `.map` to transform the result. These operations let you describe both the syntax of the input and the data that your application receives.

Put the resulting parser in an argument's [`parse`](./arguments.mdx#parsing-values) field. The library parses each value before the action runs, infers its TypeScript type, and uses the parser for help and completion.

## Build a parser

Start with a size written as `width` followed by `x` and `height`:

```ts
import { seq, uint } from "@clo4/cli";

const dimensions = seq(uint, "x", uint);
```

For `1920x1080`, the first `uint` reads `1920`, the string `"x"` matches the separator, and the second `uint` reads `1080`. The result is `[1920, 1080]`.

`seq` returns a tuple, an array with a type for each position. Only parsers contribute values to the tuple. Literal strings must match exactly, but do not appear in the result. Here, TypeScript infers `[number, number]`.

Use `.map` to transform that tuple into an object:

```ts
const size = dimensions.map(([width, height]) => ({ width, height }));
// "1920x1080" → { width: 1920, height: 1080 }
```

The result is another parser. It accepts the same text and returns `{ width: number; height: number }`. You can reuse it in several arguments or as part of a larger parser.

To try the parser directly, call `.validate` with a string:

```ts
const result = size.validate("1920x1080");
// { value: { width: 1920, height: 1080 } }
```

A successful result contains `value`. If the text does not match, the result contains `issues`, an array of problems with a `message` field.

Every parser is a named export and is also available on `CLI`. For example, `seq` and `CLI.seq` are the same function. The examples below use named imports for the parser definitions.

## Use the parser in a command

This complete example calculates the number of pixels in an image from its dimensions. It labels each number and calls `.asObject()` to return them as `{ width, height }`. Save it as `pixels.ts`:

```ts
import CLI, { seq, uint } from "@clo4/cli";

const size = seq(uint.as("width"), "x", uint.as("height")).asObject();

const spec = CLI.spec({
  name: "pixels",
  description: "Calculate the number of pixels in an image",
  options: [
    CLI.help,
    {
      name: "--size",
      description: "Image dimensions",
      args: {
        name: "size",
        default: "1920x1080",
        parse: size,
      },
    },
  ],
  subcommands: [CLI.completion],
  action({ options }) {
    const { width, height } = options.get("--size");
    console.log(width * height);
  },
});

CLI.run(spec);
```

```console
$ node pixels.ts --size 800x600
480000
$ node pixels.ts
2073600
```

The action receives an object with two numbers. The default is a string that goes through the same parser as user input. No type annotations are needed on the action.

The `.as` calls give the parts names for help. The `--size` entry shows the format and default:

```console
  --size <size>  Image dimensions (<width>x<height>, default: 1920x1080)
```

If the input does not match, the action does not run. The error names the expected part and the text before it:

```console
$ node pixels.ts --size 800*600
Error: Invalid value "800*600" for --size: expected "x" after "800"
```

The parser must consume the entire argument value. `800x600x2` fails with `unexpected "x2" after "800x600"`. A parser reads one argument value, so it does not combine separate tokens such as `--size 800 600`.

## Transform the result

`.map` takes a function whose input is the preceding parser's result. The function's return value determines the new parser's output type. It can return any type, including an object, a boolean or a number:

```ts
import { choice, seq, uint } from "@clo4/cli";

const enabled = choice("on", "off").map((value) => value === "on");
// "on" → true

const millisecondsPerUnit = { ms: 1, s: 1_000, m: 60_000, h: 3_600_000 };
const milliseconds = seq(uint, choice("ms", "s", "m", "h")).map(
  ([amount, unit]) => amount * millisecondsPerUnit[unit],
);
// "30s" → 30000
```

To reject a parsed value, throw an error from the function. The command reports the error message as an invalid value:

```ts
const even = uint.map((value) => {
  if (value % 2 !== 0) {
    throw new Error("must be even");
  }
  return value;
});
// "3" → must be even
```

Keep mapping functions free of side effects, such as writing files or changing application state. Completion also runs parsers against partially typed input and can call these functions. Put application work in the action.

## Return labelled parts as an object

`.as("name")` labels a parser. Call `.asObject()` on a `seq` to return each labelled value under its label, in place of the tuple:

```ts
import { seq, uint } from "@clo4/cli";

const size = seq(uint.as("width"), "x", uint.as("height")).asObject();
// "1920x1080" → { width: 1920, height: 1080 }
```

TypeScript infers `{ width: number; height: number }` from the labels. Help also shows each label in the format, as `<width>x<height>`.

A part without a label stays out of the object, so label only the values the action needs:

```ts
import { optional, seq, uint } from "@clo4/cli";

const major = seq(optional("v"), uint.as("major"), ".", uint).asObject();
// "v2.1" → { major: 2 }
```

A label stays on a parser through `.map`, so `uint.as("port").map(String)` and `uint.map(String).as("port")` both return their value under `port`.

Call `.asObject()` directly on the result of `seq`. `.map` and `.as` return a parser without that method. Each label can appear once in a `seq`. A repeated label is a type error, and `.asObject()` throws when it runs.

## Choose numbers and alternatives

Use `uint` for digits without a sign, `int` for signed integers, and `number()` for decimal numbers. An integer is a whole number. All three return JavaScript numbers:

| Parser                                   | Accepted examples  | Restrictions                        |
| ---------------------------------------- | ------------------ | ----------------------------------- |
| `uint`                                   | `0`, `12`, `007`   | No sign or decimal point            |
| `int`                                    | `0`, `12`, `-3`    | No decimal point                    |
| `number()`                               | `12`, `-1.5`, `.5` | Decimal notation only               |
| `number({ int: true, min: 1, max: 64 })` | `1`, `32`, `64`    | Integer within the inclusive bounds |

`int` is equivalent to `number({ int: true })`. Use `min` and `max` with or without `int` to set inclusive bounds. For dimensions, version components or other digits without a sign, use `uint`: it rejects both `-3` and `-0`.

Numbers reject empty input, surrounding whitespace, hexadecimal notation such as `0x1F`, and exponent notation such as `1e3`. A decimal point needs a digit after it, so `3.` fails. Leading zeros do not affect the result: `007` becomes `7`.

`int` and `uint` reject values outside JavaScript's safe integer range, from `-9007199254740991` to `9007199254740991`. `uint` also rejects negative values. `number()` rejects values that become infinity.

`choice` accepts strings, parsers, or both. Its output type includes each alternative's result:

```ts
import { choice, number } from "@clo4/cli";

const mode = choice("debug", "release");
// "debug" | "release"

const jobs = choice("auto", number({ int: true, min: 1, max: 64 }));
// "auto" | number
```

If several alternatives match, `choice` selects the one that consumes the most text. `choice("m", "ms")` reads `ms` as `"ms"`, regardless of their order. If alternatives consume the same amount, the first one wins.

## Add optional and repeated parts

`optional(part)` returns the part's value when it matches, or `undefined` when it does not. For example, a version can accept an optional `v` prefix:

```ts
import { optional, seq, uint } from "@clo4/cli";

const version = seq(optional("v"), uint, ".", uint, ".", uint).map(([, major, minor, patch]) => ({
  major,
  minor,
  patch,
}));
// "v7.0.0" and "7.0.0" → { major: 7, minor: 0, patch: 0 }
```

Unlike a literal string directly in `seq`, `optional("v")` contributes a value: `"v"` or `undefined`. The mapping function skips that first tuple position. The other combinators also retain the values of string parts.

Use `sepBy(part, separator)` for one or more values with a separator between them:

```ts
import { choice, sepBy } from "@clo4/cli";

const scopes = sepBy(choice("read", "write", "admin"), ",");
// "read,write" → ["read", "write"]
```

An empty list fails. A trailing separator also fails because it requires another value. Spaces are significant: this parser accepts `read,write` and rejects `read, write`.

Use `many(part)` for zero or more repetitions without a separator. Its optional second argument sets the minimum number of repetitions:

```ts
import { choice, many } from "@clo4/cli";

const permissions = many(choice("r", "w", "x"), 1);
// "rwx" → ["r", "w", "x"]
```

Without the minimum of `1`, empty input returns `[]`. These parsers preserve order and duplicate values. A rule such as unique permissions belongs in a mapping function.

## Read text between separators

`text(...stops)` reads one or more characters until a stop string or the end of the input. It leaves the stop for the next part to consume. With no stops, `text()` reads the remaining input.

This parser reads a comma-separated list of key-value pairs:

```ts
import { sepBy, seq, text } from "@clo4/cli";

const pair = seq(text("=", ","), "=", text(",")).map(([key, value]) => ({ key, value }));
const env = sepBy(pair, ",");
// "A=1,B=two" → [{ key: "A", value: "1" }, { key: "B", value: "two" }]
```

The key stops at `=` or `,`, so each pair needs its own `=`. The value stops only at `,`, so `URL=http://x?a=b` keeps the second `=` in the value. Both the key and value need at least one character.

Stops are literal strings. This definition does not provide escaping or quoting for commas within a value. Add those rules to the parser if your format needs them.

## Understand how parts consume text

Parts read from left to right without inserting or skipping characters. Each part consumes as much text as it can. After a part succeeds, a later failure does not cause it to retry a shorter match.

For example, `text()` consumes all remaining text. In `seq(text(), "=", text())`, it leaves nothing for `"="`. Use `text("=")` for the first part instead.

The same rule applies to numbers and alternatives:

```ts
import { number, seq, uint } from "@clo4/cli";

seq(number(), ".", number()); // "1.5" fails: the first number consumes "1.5".
seq(uint, ".", uint); // "1.5" → [1, 5]

seq(number(), "..", number()); // "1.5..2.5" → [1.5, 2.5]
```

Use integer parsers when a single dot separates numbers. Two dots work with `number()` because it only consumes a decimal point when a digit follows. Likewise, `choice` selects its longest match without considering what a later part needs.

## Help and completion

Help shows the input format after the argument's description. `.map` preserves that format even when it changes the output type. `.as("name")` labels a part in the pattern without changing its accepted input or output type:

| Parser definition                                | Format in help             |
| ------------------------------------------------ | -------------------------- |
| `seq(uint, "x", uint)`                           | `<int>x<int>`              |
| `seq(uint.as("width"), "x", uint.as("height"))`  | `<width>x<height>`         |
| `seq(uint, choice("s", "m", "h"))`               | `<int>(s\|m\|h)`           |
| `seq(optional("v"), uint, ".", uint, ".", uint)` | `[v]<int>.<int>.<int>`     |
| `sepBy(choice("read", "write", "admin"), ",")`   | `(read\|write\|admin),...` |

Label a combined parser to replace its whole pattern. For example, `seq(uint, "x", uint).as("dimensions")` shows `<dimensions>`. A labelled `optional` keeps its brackets, so `optional(uint).as("to")` shows `[<to>]`. A standalone number still shows its type and bounds, and a choice of strings still lists its values.

Help marks the parts of a pattern that could be misread:

| Parser definition                           | Format in help        |
| ------------------------------------------- | --------------------- |
| `seq("[", uint, "]")`                       | `"["<int>"]"`         |
| `seq(uint, choice("a\|b", "c"))`            | `<int>("a\|b"\|c)`    |
| `many(seq(uint, choice("h", "m", "s")), 1)` | `(<int>(h\|m\|s))...` |
| `sepBy(many(choice("r", "w"), 1), ",")`     | `((r\|w)...),...`     |

A literal string is in quotes when it has a character the pattern uses, such as a bracket or a `|`. A repeated part is in parentheses when its `...` could be read as repeating only the last part. A pattern too long for one line of help continues on the next.

With [shell completion installed](../guides/install-completion.mdx), the parser offers literal strings that can complete partially typed input:

| Parser                                         | Input so far | Suggestions         |
| ---------------------------------------------- | ------------ | ------------------- |
| `seq(uint, "x", uint)`                         | `1920`       | `1920x`             |
| `seq(uint, choice("s", "m", "h"))`             | `30`         | `30s`, `30m`, `30h` |
| `sepBy(choice("read", "write", "admin"), ",")` | `read,w`     | `read,write`        |
| `choice("auto", number())`                     | Empty        | `auto`              |

After `1920x`, the value still needs a height, so bash, zsh and fish leave the cursor directly after the `x`. They add a space once the value is complete, such as `30s`. Nushell never adds a space after a suggestion.

Completion does not invent numbers or arbitrary text. An argument's own `suggestions`, `suggest` or `template` take precedence over suggestions from its parser. A choice of strings also supplies spelling suggestions when a rejected argument value is close to one of them.

## Use a schema from another library

The `parse` field also accepts schemas from Zod, Valibot, ArkType and other libraries that implement Standard Schema, a shared interface for validation. These schemas parse an entire argument value. They cannot be parts in built-in combinators such as `seq` or `choice`.

[Arguments](./arguments.mdx#schemas-from-other-libraries) explains schema input types, asynchronous validation, and the information that help and completion can read from a schema.
