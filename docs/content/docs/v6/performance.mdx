Startup time affects short commands and every shell completion request. The library has no runtime dependencies. For large CLIs, `loadSpec` also avoids constructing commands that a run does not use.

The [benchmark sources](https://github.com/clo4/cli/tree/main/bench) compare startup and command execution across CLI libraries. Run them locally with `pnpm bench`. [CI records results](https://github.com/clo4/cli/blob/main/.github/workflows/cli-bench.yml) too.

## Performance comparison

The table shows elapsed time relative to `@clo4/cli` in each run. `2.5x` means a library takes 2.5 times as long. Lower is better.

| Library                                 | CI    | Apple M3 Pro |
| --------------------------------------- | ----- | ------------ |
| `node:util` parseArgs, hand-written CLI | 1.2x  | 1.3x         |
| sade                                    | 1.2x  | 1.3x         |
| Cac                                     | 1.3x  | 1.4x         |
| citty                                   | 1.6x  | 1.8x         |
| gunshi                                  | 2.3x  | 2.5x         |
| Stricli                                 | 2.5x  | 2.3x         |
| brocli                                  | 2.9x  | 2.0x         |
| Cliffy                                  | 3.1x  | 3.0x         |
| Commander                               | 4.4x  | 3.4x         |
| clerc                                   | 4.6x  | 3.6x         |
| cmd-ts                                  | 5.2x  | 4.0x         |
| Clipanion                               | 5.4x  | 4.4x         |
| Optique                                 | 13.0x | 13.9x        |
| oclif                                   | 16.0x | 16.2x        |
| Yargs                                   | 18.0x | 20.7x        |
| Effect                                  | 18.2x | 18.2x        |

Each column is a separate run. The benchmark measures seven tasks, including help, nested commands and argument errors. Timing starts before loading the bundled CLI and ends when the process exits. It excludes Node's own startup time.

Each library's score is the geometric mean of its task medians, minus the cost of loading an empty bundle. Ratios compare those scores, not total wall-clock time from a shell invocation.

## When loading on demand is faster

[Load commands on demand](./loading-commands.mdx) covers the implementation. The measurements below compare constructing the whole spec, deferring construction and importing command groups separately.

These measurements run one command from a bundled CLI on an Apple M3 Pro. Each command defines six options. Times exclude Node startup and stdout initialization.

| Commands | No `loadSpec` | Command from the same file | Command from a file per group |
| -------- | ------------- | -------------------------- | ----------------------------- |
| 10       | 1.6 ms        | 1.7 ms                     | 1.9 ms                        |
| 50       | 1.9 ms        | 1.9 ms                     | 2.0 ms                        |
| 100      | 2.4 ms        | 2.2 ms                     | 2.0 ms                        |
| 1,000    | 12.9 ms       | 7.8 ms                     | 2.3 ms                        |

In these measurements, reading another file costs about 0.3 ms. Loading by group starts to help at roughly 50 commands. Deferring construction within one file starts to help at roughly 25 commands and adds about 0.03 ms below that point.

These thresholds depend on the spec, application imports and machine. Use the benchmarks to compare the forms that your CLI can use.

### Large CLI comparisons

The large-CLI benchmark measures command execution, root help, group help and unknown commands. It compares one-file builds and builds with a file per command group. A hand-written CLI using `parseArgs` provides a baseline.

The one-file comparison includes `@clo4/cli`, Commander, Yargs, citty, sade, Cliffy, Stricli and gunshi. sade has no command groups, so it has no group-help measurement. `@clo4/cli` uses synchronous loaders, with a second measurement for a fully constructed spec.

The file-per-group comparison includes `@clo4/cli`, citty, Cliffy, Stricli and gunshi. Stricli and gunshi keep command definitions in the entry file and load actions separately. citty and Cliffy load every group's file for root help. citty also does this for an unknown command.

oclif is absent from the large-CLI comparison because its per-command manifest does not fit the single-bundle setup. Cac, Clipanion, Effect, Optique, clerc, cmd-ts and brocli do not yet have large-CLI fixtures.

Help measurements pipe output to another program. Terminal output adds Node's stdout initialization cost, which this library avoids for its own help output.
