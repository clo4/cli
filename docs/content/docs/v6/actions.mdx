title: Actions

An action is the function attached to a command or option. The parser selects it after reading the command line.

A command action receives input that satisfies the command's argument counts and option rules. Values are strings. Convert and validate them in the action, with ordinary TypeScript or your preferred validation library.

## Validating values

```ts
import * as CLI from "@clo4/cli";

const spec = CLI.spec({
  name: "serve",
  options: [
    {
      name: "--port",
      description: "Listen on this port.",
      args: { name: "port", default: "8080" },
    },
  ],
  action({ options }) {
    const port = Number(options.get("--port"));
    if (!Number.isInteger(port) || port < 1 || port > 65535) {
      throw new Error("Port must be an integer between 1 and 65535");
    }
    console.log(`Port: ${port}`);
  },
});

CLI.run(spec);
```

```console
$ node serve.ts --port 3000
Port: 3000
$ node serve.ts --port nope
Error: Port must be an integer between 1 and 65535
```

The parser requires a value after `--port`. The action decides whether that value is a valid port.

Completion suggestions do not restrict accepted values. If a value must belong to a fixed set, enforce that set in the action.

## Errors and exit codes

If an action throws an `Error`, `CLI.run` prints its message to stderr and returns exit code `1`. It does not print a stack trace. To report an error without throwing, call `CLI.printError("message")` and return `1`.

Return a number to set the exit code. Returning nothing means success, code `0`. Async actions are awaited. Exit codes are limited to `0`–`255`.

Parsing errors also return `1`. They include usage information and, when a close match exists, a spelling suggestion. Errors thrown by an action do not include usage automatically.

`CLI.run` resolves to the exit code and sets `process.exitCode`. It never calls `process.exit`, so the process can finish pending work.

## Option actions

An option can define an action. This takes precedence over the command's action:

```ts
import * as CLI from "@clo4/cli";

const spec = CLI.spec({
  name: "demo",
  args: { name: "input" },
  options: [{ name: "--version", action: () => console.log("1.0.0") }],
  action({ args: [input] }) {
    console.log(input);
  },
});

CLI.run(spec);
```

`demo --version` prints the version without requiring `input`. If several supplied options have actions, the last one wins.

Option actions bypass positional argument counts, required options and option relationships. They still reject unknown options and malformed option values. This is how `--help` works without requiring the rest of the command's inputs.

Because those checks are skipped, option actions receive `args` as `string[]`, and `options.get` can return `undefined`. TypeScript still checks option names.

## Execution context

An action receives the command's positional values in `args` and named inputs through `options`. It also receives the selected command path, the position of `--`, and a function that returns help text.

The path describes the invocation, from the root to the selected command. Loaded commands can appear as copies, so read their fields rather than comparing object identity.

[ActionInit](./reference/cli/interfaces/ActionInit.mdx) documents these fields. [OptionArgs](./reference/cli/interfaces/OptionArgs.mdx) documents the option reader and its underlying map.

## Types in actions

`CLI.spec` infers each action's inputs from its command, including persistent options inherited from ancestors:

```ts
import * as CLI from "@clo4/cli";

const spec = CLI.spec({
  name: "demo",
  options: [{ name: "--verbose", isPersistent: true }],
  subcommands: [
    {
      name: "build",
      args: [{ name: "source" }, { name: "destination", isOptional: true }],
      options: [{ name: "--output", args: { name: "dir", default: "dist" } }],
      action({ args: [source, destination], options }) {
        source; // string
        destination; // string | undefined
        options.get("--output"); // string
        options.has("--verbose"); // boolean
      },
    },
  ],
});

CLI.run(spec);
```

`CLI.command` provides the same inference for a separately defined command. Its types only include options visible in that definition. Placing it under a parent does not add inherited option names to its action's types.

When sharing an option or argument between commands, preserve its literal types with `as const`:

```ts
const reason = {
  name: "--reason",
  description: "Reason for the change.",
  args: { name: "text" },
} as const;
```

Without `as const`, the name widens to `string`. The action then accepts any option name. Fields such as `isOptional: true` also need their literal types preserved.

## Running a command line

`CLI.run` reads `process.argv.slice(2)` by default. A caller can supply `argv` and disable changes to `process.exitCode`. This lets tests invoke the CLI without starting another process.

[Test command invocations](./testing-commands.mdx) shows that pattern. [RunOptions](./reference/cli/interfaces/RunOptions.mdx) lists the runner's configuration.

In an entry file that uses [loaded commands](./loading-commands.mdx), call `CLI.run(spec)` without top-level `await` to avoid an extra shared chunk when bundling.
