title: Parser settings
description: Understand parsing boundaries, abbreviations and option forms.
---

`parserDirectives` changes how a command interprets tokens. Each directive is inherited independently. A descendant keeps its parent's value until it supplies an override.

The defaults suit a CLI with named subcommands and conventional short and long options. Change a directive when the command's syntax needs a different boundary or matching rule.

## Options before arguments

Normally, options can appear before or after positional arguments. A wrapper needs to stop interpreting its own options when the wrapped command starts.

`optionsMustPrecedeArguments: true` makes the first positional argument that boundary. Every later token becomes a positional value, including option names and `--`.

[Wrap another executable](./wrapping-commands.mdx) shows a complete wrapper. For a single invocation without changing the command definition, users can supply `--` explicitly.

## Abbreviated subcommands

`subcommandsMatchUniquePrefix: true` lets a visible local subcommand match an unambiguous prefix. With `install` and `info`, `ins` selects `install`, `inf` selects `info`, and `in` is ambiguous.

Hidden and inherited subcommands require exact names. Exact matching is also the default for ordinary subcommands.

Combining positional arguments with prefix matching means a value can also look like a command abbreviation. [Spec validation](./testing.mdx#abbreviated-commands-and-positional-arguments) rejects this combination unless explicitly allowed.

## Option value separators

A separator joins an option name to its value in one token, as in `--port=3000`. `optionArgSeparators` replaces the inherited list of separators.

For example, `[":", "="]` accepts `--port:3000` and `--port=3000`. A single string accepts one separator. An empty array disables separators. Short attached forms such as `-p3000` work independently of that list.

An attached value ends the values for that use of the option. An option that takes several values needs separate tokens, such as `--size 80 24`.

### Requiring a separator

An option's `requiresSeparator` field can require an attached value. `true` accepts any enabled separator. A string requires that particular separator, which must also be enabled by the command's directives.

With the default separator, `requiresSeparator: true` accepts `--port=3000` and rejects `--port 3000`. Spec checks reject configurations with no usable option form.

## Literal option names

Conventional short options chain: `-abc` can mean `-a -b -c`. `flagsArePosixNoncompliant: true` disables that interpretation and reads names such as `-name` literally.

This directive also treats unrecognized option-like tokens as positional arguments. The command still needs enough positional capacity to accept them.

For a `find`-style interface, an option named `-name` can take a pattern. Users must quote patterns such as `'*.ts'` when the shell must pass them without expanding them first.
