Actions used to receive every value as a string. If `--port` needed a number, you'd convert it in the action, check the range yourself, and print your own error. Now you can give an argument a `parse`, and your action receives the parsed value:

```ts
import * as CLI from "@clo4/cli";

const spec = CLI.spec({
  name: "serve",
  args: { name: "root", description: "Folder to serve" },
  options: [
    CLI.help,
    {
      name: "--port",
      description: "Listen on this port",
      args: {
        name: "port",
        default: "8080",
        parse: CLI.number({ min: 1, max: 65535, int: true }),
      },
    },
    {
      name: "--mode",
      description: "Build mode",
      isRequired: true,
      args: {
        name: "mode",
        parse: CLI.choice(["debug", "release"]),
      },
    },
  ],
  action({ args: [root], options }) {
    options.get("--port"); // number
    options.get("--mode"); // "debug" | "release"
  },
});

CLI.run(spec);
```

`CLI.number` and `CLI.choice` are built in. The default `"8080"` goes through `parse` like a value the user typed, so your action gets the number `8080`.

## Every problem at once

Every `parse` runs before your action. If any value is rejected, the action doesn't run. This command line leaves out `root` and gets both values wrong, and the user sees all three problems together:

```console
$ serve --port 70000 --mode fast
Error: Expected 1 argument
Error: Invalid value "70000" for --port: expected an integer from 1 to 65535
Error: Invalid value "fast" for --mode: expected debug | release

Usage:
  serve --mode <mode> [flags] <root>

Arguments:
  root  Folder to serve

Flags:
  -h, --help     Print a help message
  --port <port>  Listen on this port (integer from 1 to 65535, default: 8080)
  --mode <mode>  Build mode (debug | release)
```

Version 6.0 printed only the first problem, so the user had to fix it and run the command again to find the next one. Now every problem gets its own `Error:` line, followed by the help once. That covers missing arguments and required options, `dependsOn` and `exclusiveOn` rules the command line breaks, and values a `parse` rejects.

If an unknown option is provided, it will be the only error reported, because the parser can't tell what the words after it mean.

## Zod, ArkType and Valibot

`parse` takes any [Standard Schema](https://standardschema.dev), the shared interface that Zod, ArkType, Valibot and other validation libraries implement. If you already validate config or API input with one of them, your command line can use the same schemas:

```ts
import { type } from "arktype";
import { z } from "zod";
import * as CLI from "@clo4/cli";

const spec = CLI.spec({
  name: "deploy",
  options: [
    CLI.help,
    {
      name: "--region",
      description: "Region to deploy to",
      args: { name: "region", parse: z.enum(["us-east", "eu-west", "ap-south"]) },
    },
    {
      name: "--replicas",
      description: "Number of replicas",
      args: { name: "count", default: "2", parse: z.coerce.number().int().min(1).max(10) },
    },
    {
      name: "--env",
      description: "Environment",
      args: { name: "env", parse: type("'production' | 'staging'") },
    },
  ],
  subcommands: [CLI.completion],
  action({ options }) {
    options.get("--region"); // "us-east" | "eu-west" | "ap-south" | undefined
    options.get("--replicas"); // number
    options.get("--env"); // "production" | "staging" | undefined
  },
});

CLI.run(spec);
```

TypeScript gives each value the schema's output type. Async schemas work too. A rejected value shows the schema's own message:

```console
$ deploy --replicas 40
Error: Invalid value "40" for --replicas: Too big: expected number to be <=10
```

Help and completion read a schema's choices and number range from the JSON Schema it returns through `~standard.jsonSchema`, the same way they read `CLI.number` and `CLI.choice`. Zod and ArkType schemas have it with no setup, so you don't need to list their values in the option's description. The tests cover Zod 4.6 and ArkType 2.2:

```console
$ deploy --help
Usage:
  deploy [flags]

Commands:
  completion  Print a shell completion script

Flags:
  --region <region>   Region to deploy to (us-east | eu-west | ap-south)
  --replicas <count>  Number of replicas (integer from 1 to 10, default: 2)
  --env <env>         Environment (production | staging)

Global flags:
  -h, --help          Print a help message
```

Pressing Tab after `--region` offers `us-east`, `eu-west` and `ap-south`, and after `--env` it offers `production` and `staging`.

Valibot schemas have no `~standard.jsonSchema`, so they parse values and add nothing to help or completion. For a Valibot schema, list the values in the option's description and give the argument a `suggestions` array.

## Upgrading

A CLI written for 6.0 runs unchanged. Two kinds of test can need updating:

- A test that compares error output for a command line with several problems. It now gets one `Error:` line for each problem.
- A test that passes an action a hand-built `options` object typed as `CLI.OptionArgs`. That object no longer compiles until its `get` and `all` are generic, as in `get<Read>(name: string): Read | undefined`. You can drop the hand-built object and run the command with `CLI.run(spec, { argv: ["--port", "3000"], setExitCode: false })` instead, which leaves `process.exitCode` alone.

The minified bundle grew from 33.5 kB to 39.2 kB, and importing it takes 0.09 ms longer, even in a CLI that doesn't use `parse`. The [release notes](https://github.com/clo4/cli/releases/tag/v6.1.0) have the benchmark details, the new spec checks and the full list of changes.
